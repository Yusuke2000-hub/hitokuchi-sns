# Hitokuchi 要件定義書

## 1. プロジェクト概要

### 背景・目的

「Hitokuchi（一口）」は、X/Twitter を参考にした短文投稿型 SNS アプリです。RaiseTech AI 講座の学習課題として開発します。

テキストと画像の投稿、いいね・コメント・フォロー機能を備え、インプレッション数やリツイートを省いた「純粋な交流」に特化したシンプルな SNS を目指します。

### 利用者像

- SNS に慣れた一般ユーザー（10 代〜30 代）
- スマートフォン・PC の両方で利用する

### 利用環境

| 種別 | 対象 |
|---|---|
| ブラウザ | Google Chrome 最新版・Safari 最新版 |
| デバイス | PC・スマートフォン（レスポンシブ対応） |
| 通信 | インターネット接続必須 |

---

## 2. 機能要件（スコープ）

詳細は [機能一覧](./features.md) を参照してください。

- ユーザー登録・ログイン（メールアドレス＋パスワード、JWT 認証）
- 投稿（テキスト 280 文字制限、画像添付可、自分の投稿のみ編集・削除可）
- タイムライン（全体・フォロー中の 2 種類、タブ切替）
- いいね（数を表示）
- コメント（数を表示、投稿者ユーザー名を表示）
- プロフィール（ユーザー名・アイコン・自己紹介、フォロー／フォロワー）
- ユーザー検索（ユーザー名での検索、ユーザー名クリックでプロフィールへ遷移）

---

## 3. 非機能要件

| 種別 | 要件 |
|---|---|
| パフォーマンス | タイムライン初期表示 3 秒以内（通常回線） |
| セキュリティ | JWT によるステートレス認証、HTTPS 通信、パスワードの bcrypt ハッシュ化 |
| 可用性 | EC2 は 1 台構成のため単一障害点は残る。ALB は入口の一本化・HTTPS 終端の役割を担い、将来 EC2 を複数台に増やす際の拡張基盤として機能する |
| スケーラビリティ | RDS によるデータベース分離、S3 による画像ストレージ分離 |
| 保守性 | レイヤードアーキテクチャ（Controller → Service → Repository）の厳守 |

---

## 4. 制約

| 種別 | 内容 |
|---|---|
| 文字数 | 投稿テキスト 280 文字以内 |
| 画像 | 1 投稿につき 1 枚、AWS S3 に保存 |
| 認証方式 | メールアドレス＋パスワードのみ（OAuth・SNS ログインはスコープ外） |
| X/Twitter との差別化 | インプレッション数は表示しない、リツイート機能はなし |
| 技術スタック | [技術スタック](./tech-stack.md) を参照 |

---

## 5. 開発の進め方

- Git ブランチ運用：main ブランチへの直接 push 禁止、feature ブランチで作業
- ブランチ名：`feature/{issue番号}-{機能名}` 形式
- PR 作成時：本文に `Closes #{issue番号}` を記載し、マージ時に自動クローズ
- 変更は一度に大きくまとめず、1 件ずつ確認しながら進める
