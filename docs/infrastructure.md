## 概要

AWS 上に EC2 + RDS + ALB + S3 の構成でインフラを構築します。Terraform でインフラをコードとして管理し、環境の再現性を確保します。EC2 上で Nginx がリバースプロキシとして動作し、`/api/*` へのリクエストを Spring Boot に転送、それ以外は React のビルド済み静的ファイルを直接配信します。

| サービス | 用途 | 備考 |
|---|---|---|
| EC2 | アプリケーションサーバー | Amazon Linux 2023、t3.small 程度 |

| ACM | SSL/TLS 証明書 | ALB に適用 |

## Nginx リバースプロキシ設定方針

```nginx
server {
    listen 80;
    server_name example.com;

    # /api/* は Spring Boot にプロキシ
    location /api/ {
        proxy_pass http://localhost:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }

    # /* は React のビルド済み静的ファイルを配信
    location / {
        root /var/www/hitokuchi/dist;
        index index.html;
        try_files $uri $uri/ /index.html;
    }
}
```

- `/api/*` へのリクエストは Spring Boot（:8080）にプロキシする
- `/*` へのリクエストは `npm run build` で生成した `dist/` ディレクトリの静的ファイルを Nginx が直接配信する
- React Router の SPA ルーティングに対応するため `try_files` で `index.html` にフォールバックする
- `:5173` は開発環境専用（本番環境では使用しない）

## セキュリティ（ポート・アクセス制御）

### セキュリティグループ設定方針

| リソース | インバウンド | アウトバウンド |
|---|---|---|
| ALB | 80（HTTP）全許可、443（HTTPS）全許可 | EC2 の 80 へ |
| EC2 | 80（ALB のセキュリティグループから）、22（管理者 IP から）| すべて許可 |
| RDS | 5432（EC2 のセキュリティグループから） | 不要 |
| S3 | - | IAM ロールで EC2 からのアクセスを許可 |

### その他のセキュリティ方針

- EC2 にはパブリック IP を直接割り当てず、ALB 経由でのみアクセスを受け付ける
- RDS はプライベートサブネットに配置し、外部からの直接アクセスを遮断する
- JWT の秘密鍵は環境変数で管理し、コードには含めない
- HTTPS は ALB で SSL 終端し、EC2 内部は HTTP で通信する

## Terraform 構成概要

`terraform/` ディレクトリで管理するリソース一覧：

| リソース | 概要 |
|---|---|
| VPC | パブリック・プライベートサブネット、IGW |
| Security Groups | ALB・EC2・RDS それぞれのセキュリティグループ |
| EC2 | AMI・インスタンスタイプ・キーペア |
| RDS | PostgreSQL 17、マルチ AZ は学習用のため無効 |
| ALB | リスナー（80/443）、ターゲットグループ |
| S3 | バケット、バケットポリシー |
| IAM | EC2 が S3 にアクセスするためのロール |
| ACM | SSL 証明書（ドメインが必要） |

## デプロイ手順概要

1. Terraform を実行してインフラを構築する（`terraform apply`）
2. EC2 に SSH ログインし、Java 21 と Nginx をインストールする
3. フロントエンドをビルドする（`npm run build`）
4. ビルド成果物（`dist/`）を EC2 の `/var/www/hitokuchi/dist/` に配置する
5. バックエンドを JAR ファイルにビルドする（`./gradlew bootJar`）
6. JAR ファイルを EC2 に転送し、systemd サービスとして起動する
7. Nginx の設定ファイルを配置してリロードする（`nginx -s reload`）
8. ALB のターゲットグループのヘルスチェックが通ることを確認する
9. ブラウザからドメインにアクセスして動作確認する
